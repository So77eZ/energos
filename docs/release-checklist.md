# Чек-лист релиза MVP

Собран по коду ветки `mvp-fixes` (#340) и проверкам в docker, 19.10.2026. Отмечайте пункты
по ходу выкладки.

## 1. Блокеры — без них не выпускать

- [x] **HTTPS — сделано в #340.** Cookie входа в проде ставится с `Secure`
  (`frontend/src/shared/lib/session.ts`), а браузер не сохраняет `Secure`-cookie по обычному
  HTTP — без HTTPS на настоящем домене **вход не заработает** (на localhost это не видно: он
  считается безопасным). Теперь:
  - адрес сайта в `server/Caddyfile` — `PUBLIC_URL` как есть. `https://<домен>` — Caddy сам
    получает сертификат Let's Encrypt и редиректит `http → https`; `http://localhost` — только
    HTTP на `:80`, как раньше локально (но отвечает только на `localhost`, не на `127.0.0.1`/IP);
  - у `server` в `docker-compose.yml` порты `80`, `443`, `443/udp` (HTTP/3) и тома
    `caddy_data`/`caddy_config` — сертификат переживает пересоздание контейнера.
- [ ] **Домен и DNS.** Купить домен, A-запись (и AAAA, если есть IPv6) на IP сервера; решить про
  `www` (редирект на основной). Сертификат выпустится, только когда DNS уже указывает на сервер и
  порты 80/443 открыты.
- [x] **`frontend/.env.local` не попадает в образ — сделано в #340.** Раньше при сборке с машины
  разработчика dev-значения (`NEXT_PUBLIC_ORIGIN=http://localhost:3001`) вшивались в серверный код
  фронта. Теперь `.env*.local` в `frontend/.dockerignore`; проверено в собранном образе.
- [x] **Адрес сайта во фронте — сделано в #340.** Раньше фронт брал его из `NEXT_PUBLIC_ORIGIN`,
  который Next вшивает при сборке, а compose передавал только при запуске — в образ попадало
  не то. Теперь фронт читает `PUBLIC_URL` на сервере во время запроса: одно значение в `.env`
  на всех, без пересборки при смене.
- [x] **Перезапуск после перезагрузки сервера — сделано в #340.** У всех сервисов
  `restart: unless-stopped`; проверить, что Docker включён в автозагрузку
  (`systemctl enable docker`).

## 2. `.env` на сервере

- [ ] `DEPLOY_ENV=prod` — тогда Caddy не проксирует `/api` наружу (бэк, `/api/docs` и
  `/api/openapi.json` снаружи недоступны).
- [ ] `PUBLIC_URL=https://<домен>` — из него берутся адрес сайта для Caddy (HTTPS), ссылки в
  письмах (`/auth/verify`, `/auth/reset-password`) и заголовок `Origin` запросов фронта к бэку. **Без `/` в конце**:
  Caddy примет его за путь и будет отдавать только главную.
- [ ] `ACCESS_TOKEN_SECRET`, `RESET_PASSWORD_TOKEN_SECRET`, `VERIFICATION_TOKEN_SECRET` — новые,
  случайные, разные, не короче 32 символов (бэк не стартует с короче), не те, что в dev.
  Например, `openssl rand -hex 32` на каждый.
- [ ] `DB_PASSWORD` — новый и стойкий; `DB_USER`/`DB_NAME` по вкусу.
- [ ] `TOKEN_LIFETIME_SECONDS=86400` (24 ч, refresh-токена нет — договорились «пробуем так»).
- [ ] `SMTP_*` — боевой ящик (старый пароль из `.env.example` сменён). `SMTP_FROM` — тот же адрес,
  что и ящик, иначе письма уйдут в спам или будут отклонены.
- [ ] Флаги фронта `NEXT_PUBLIC_FF_*` при сборке **не задавать**: всё вне MVP (избранное, эмодзи,
  аватарки, заявки, достижения, рулетка, лидерборд, редакторская оценка) должно остаться выключенным.

## 3. Сервер

- [ ] Наружу открыты только 80 и 443 (и SSH). Postgres, бэк (8000) и фронт (3000) портов на хост не
  публикуют — так и есть в compose, проверить, что файрвол не открывает лишнего.
- [ ] Данные БД — в `./data/postgres` рядом с compose. Настроить ежедневный `pg_dump` с хранением
  вне сервера; проверить восстановление из дампа хотя бы один раз.
- [ ] Миграции применяются сами при старте бэка (`alembic upgrade head` в `backend/Dockerfile`).
  Перед обновлением прода — дамп БД.
- [ ] Лимиты запросов хранятся в памяти процесса бэка (один uvicorn-воркер) и сбрасываются при
  перезапуске — это ок для MVP; не запускать несколько воркеров без общего хранилища лимитов.
- [ ] Первый администратор: зарегистрироваться через сайт, затем в БД выставить своему пользователю
  `is_superuser = true` и `is_verified = true` (через `psql` в контейнере `postgres`).

## 5. Проверка после выкладки

- [ ] `http://<домен>` редиректит на `https://`, сертификат валиден.
- [ ] `https://<домен>/api/v1/energy-drinks/` снаружи **не** отдаёт JSON (в проде `/api` закрыт).
- [ ] Главная, каталог, tier list, сравнение, карта вкусов открываются без ошибок, картинки
  напитков грузятся (`/drink-image/{id}`).
- [ ] Регистрация с именем → письмо пришло, ссылка ведёт на `https://<домен>/auth/verify?token=…`,
  подтверждение проходит.
- [ ] Вход и выход работают, после перезагрузки страницы пользователь остаётся залогинен
  (проверка `Secure`-cookie).
- [ ] «Забыли пароль?» → письмо → смена пароля → вход с новым.
- [ ] Отзыв: создать (с общей оценкой), изменить, удалить; повторный отзыв невозможен; счётчик на
  странице напитка обновляется сразу.
- [ ] Профиль: вкладка «Отзывы» показывает свои отзывы с напитками.
- [ ] Админ: создать напиток, загрузить большое фото с телефона (сожмётся в браузере), изменить,
  удалить.
- [ ] Поиск в каталоге с опечаткой находит напиток.
- [ ] Мобильная вёрстка (360–390 px): каталог, страница напитка, меню.
