# MVP: задачи на стыке фронта и бэка

Актуально для ветки `mvp-fixes` (#340, 19.10.2026). Всё отмеченное «проверено»
проверялось запуском стека в docker (бэк + Postgres + Caddy + фронт), а не чтением кода.

Фронт работает с API ветки `mvp` (`docs/api.md`, `backend/api/v1/*`). Где API не хватает,
он обходится адаптером или прячет фичу за флагом (`frontend/src/shared/config/features.ts`).
Ниже — что осталось сделать, чтобы обходы убрать.

Обозначения: 🔴 блокер (сломано сейчас) · 🟡 задача бэку · ❓ нужно решение ·
🔵 задача фронта (ждёт бэк или сделаем сами) · ✅ сделано.

Как пользоваться: взяли задачу — отметьте её в PR/комментарии и вычеркните здесь, когда
влили. Пункт закрывается тем коммитом, который его делает; про фронтовые хвосты
(убрать адаптер, включить флаг) фронт сделает сам после вашего ответа.

## 2. Задачи бэку

### B3. 🟡 Общий список отзывов (после MVP)
- **Сейчас:** `GET /reviews/` отдаёт отзывы только одного напитка (`energy_drink_id` обязателен).
- **Что не работает:** лента «последние отзывы» в шапке (пустая) и лидерборд в админке (флаг
  `reviewAuthors`) — им нужны отзывы всех напитков с авторами и датами.
- **Нужно:** `GET /reviews/` без обязательного `energy_drink_id` (или отдельный эндпоинт «последние
  отзывы»). Можно отложить на после MVP.

### B6. 🟡 Картинки напитков
- (а) ~~Напиток без картинки отдаёт `200` с пустым телом~~ — исправлено в `568a3fc`, теперь
  `404 IMAGE_NOT_FOUND`.
- (б) Нет `Cache-Control`/`ETag`/`Last-Modified` — картинка (до 1 МБ) качается заново на
  каждый просмотр страницы. Пока фронт кеширует сам (`/drink-image/{id}`, 5 минут).
- (в) С `efc5378` бэк при сохранении перекодирует картинку в WebP (качество 75), но размер в
  пикселях не меняет. Фронт перед загрузкой уменьшает фото больше лимита (до 1600 px по длинной
  стороне, WebP). Миниатюры для карточек (`?w=`) — по желанию, после MVP.
- (г) В схеме напитка нет признака «картинка есть» (`has_image`/`image_url`) — фронт узнаёт
  о её отсутствии только по ошибке загрузки.
- (д) Лимит картинки дублируется на фронте (константа `MAX_IMAGE_BYTES` в `DrinkForm`) — хорошо бы
  отдавать его откуда-то. `413` с `77fae3c` приходит в общем формате, `413 CONTENT_TOO_LARGE`.

## 7. После MVP

- **Рулетка: случайные N напитков с бэка** (идея бэкендера в ревью #330). Серверная функция/эндпоинт,
  который отдаёт случайные напитки в количестве, ограниченном заданным значением (параметр
  `limit`), чтобы рулетка не тянула весь каталог. Фронт тогда перестанет грузить весь список ради
  рулетки и заменит `fetchGachaponPool` (`features/gachapon/actions.ts`) на этот запрос.
