# MVP: задачи на стыке фронта и бэка

Актуально для `mvp` на коммите `f14c044` (15.10.2026). Всё отмеченное «проверено»
проверялось запуском стека в docker (бэк + Postgres + Caddy + фронт), а не чтением кода.

Фронт работает с API ветки `mvp` (`docs/api.md`, `backend/api/v1/*`). Где API не хватает,
он обходится адаптером или прячет фичу за флагом (`frontend/src/shared/config/features.ts`).
Ниже — что осталось сделать, чтобы обходы убрать.

Обозначения: 🔴 блокер (сломано сейчас) · 🟡 задача бэку · ❓ нужно решение ·
🔵 задача фронта (ждёт бэк или сделаем сами) · ✅ сделано.

Как пользоваться: взяли задачу — отметьте её в PR/комментарии и вычеркните здесь, когда
влили. Пункт закрывается тем коммитом, который его делает; про фронтовые хвосты
(убрать адаптер, включить флаг) фронт сделает сам после вашего ответа.

## 1. Блокеры

### 🔴 `POST /energy-drinks/` отвечает `500`
- **Проверено на `f14c044`:** в логе `AttributeError: 'EnergyDrinkService' object has no attribute
  'read_schema'` (`services/base.py:36`, `create`). `BaseService.__init__` принимает `read_schema`,
  но `EnergyDrinkService` его не задаёт. Админка не может создать напиток; `PUT`/`DELETE`
  и загрузку картинки через `update_image` стоит проверить тем же способом.
- **Нужно:** передать `read_schema` (`EnergyDrinkReadSchema`) при создании сервиса.

Найденные ранее `created_at: str` (`500` на ответах со схемой напитка) и `/count` (`422`,
перехватывался `/{id}`) исправлены в `a756494` и `0f1594d` — см. раздел «Уже сделано».

## 2. Задачи бэку

### B3. 🟡 В отзывах нет `energy_drink_id` и даты
- **Сейчас (`8c3eebe`, проверено):** `GET /reviews/?energy_drink_id=…`, `GET /reviews/me` и ответы
  `POST`/`PUT` отдают `id`, `rating`, оценки, `comment` и автора `user: {id, username, role}`.
  `energy_drink_id` и `created_at` в ответе нет; `GET /reviews/` без `energy_drink_id` — `422`.
- **Что делает фронт:** отзывы напитка берёт по `energy_drink_id` из запроса, «мой отзыв» на
  странице напитка находит по `user.id`. Не получается: вкладка «Мои отзывы» в профиле (в
  `/reviews/me` не видно, к какому напитку отзыв), сортировка отзывов по дате, лента «последние
  отзывы» в шапке и лидерборд в админке (нужен общий список отзывов) — они выключены флагом
  `reviewAuthors` или пусты.
- **Нужно:** `energy_drink_id` (и желательно имя/id напитка) и `created_at` в `ReviewReadSchema`.
  Для ленты и лидерборда — ещё `GET /reviews/` без обязательного `energy_drink_id` (или отдельный
  эндпоинт «последние отзывы»); это можно отложить на после MVP.

### B6. 🟡 Картинки напитков
- (а) ~~Напиток без картинки отдавал `200` с пустым телом~~ — на `f14c044` отвечает `404`
  (проверено в docker).
- (б) Нет `Cache-Control`/`ETag`/`Last-Modified` — картинка (до 1 МБ) качается заново на
  каждый просмотр страницы. Пока фронт кеширует сам (`/drink-image/{id}`, 5 минут).
- (в) Оригинал отдаётся как есть. Лучше уменьшать при загрузке (≈800 px, WebP/JPEG ~80%) или
  отдавать миниатюру по `?w=`.
- (г) В схеме напитка нет признака «картинка есть» (`has_image`/`image_url`) — фронт узнаёт
  о её отсутствии только по ошибке загрузки.
- (д) `413` при превышении `MAX_ENERGY_DRINK_IMAGE_SIZE` приходит текстом
  `Content Too Large`, а не JSON `{"detail": …}`. Лимит дублируется на фронте (константа
  `MAX_IMAGE_BYTES` в `DrinkForm`) — хорошо бы отдавать его откуда-то.

## 3. Нужны решения

### D3. ❓ Серверные фильтры и поиск по названию
- **Сделано в `8c3eebe`:** `avg_rating`, `reviews_count`, `avg_*` в схеме напитка, `order_by`
  по ним и `order_direction`. Фронт берёт рейтинги оттуда (#335).
- **Осталось решить:** каталог, tier list, сравнение и карта вкусов по-прежнему фильтруют и
  ищут по названию по **всему** списку на клиенте, поэтому фронт забирает все напитки страницами
  (по `/count`). Нужны ли серверные фильтры (по `no_sugar`, цене, диапазону рейтинга) и поиск по
  названию, чтобы грузить страницами по требованию, или оставляем «грузим всё» на MVP?

## 7. После MVP

- **Рулетка: случайные N напитков с бэка** (идея бэкендера в ревью #330). Серверная функция/эндпоинт,
  который отдаёт случайные напитки в количестве, ограниченном заданным значением (параметр
  `limit`), чтобы рулетка не тянула весь каталог. Фронт тогда перестанет грузить весь список ради
  рулетки и заменит `fetchGachaponPool` (`features/gachapon/actions.ts`, ветка #330) на этот запрос.
