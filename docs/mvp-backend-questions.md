# MVP: вопросы к бэкенду

Фронт переводится на API ветки `mvp` (`docs/api.md`, `backend/api/v1/*`). Где API не хватает,
фронт временно обходится адаптером или прячет фичу за флагом
(`frontend/src/shared/config/features.ts`). Ниже — что нужно от бэка, чтобы обходы убрать.
Каждый пункт: что сейчас, что делает фронт, что нужно.

Файл живёт в репозитории: отвечайте прямо в нём (правкой или комментарием в PR) —
по мере ответов фронт убирает костыли.

## Блокирующее для полного функционала

### 1. Роль пользователя не отдаётся
- **Сейчас:** `models/user.py` хранит `role`, но `UserRead` (`schemas/user.py`) её не содержит.
- **Фронт:** админ определяется по `is_superuser`; если в ответе появится `role` — берётся он (`entities/user/api/authApi.ts`).
- **Нужно:** добавить `role` в `UserRead`. Иначе админка зависит от того, совпадают ли `is_superuser` и `role=admin`.

### 2. В выдаче отзывов нет связей и автора
- **Сейчас:** `GET /reviews/` и отзывы внутри `GET /energy-drinks/` отдают только оценки (+ `id` в `/reviews/`): нет `energy_drink_id`, `user_id`, `comment`, дат; у вложенных отзывов нет и `id`.
- **Фронт:** отзывы собираются из вложенных в напитки, `id` синтетические (отрицательные), автор/комментарий/даты пустые. Карточка «мой отзыв», правка и удаление, список отзывов с авторами выключены флагом `reviewAuthors`.
- **Нужно:** в `ReviewSchema` и вложенных отзывах — `id`, `energy_drink_id`, `user_id`, `comment`, `created_at`, `updated_at`, публичное имя автора (см. п. 6).

### 3. «Мои отзывы»
- **Сейчас:** эндпоинта нет.
- **Фронт:** вкладка «Мои отзывы» в профиле пустая (`reviewApi.myReviews` возвращает `[]`).
- **Нужно:** `GET /reviews/me` (или фильтр `user_id` в `GET /reviews/`).

### 4. `comment` при создании отзыва
- **Сейчас:** `ReviewCreateSchema` без `comment`, `ReviewUpdateSchema` — с ним.
- **Фронт:** шлёт `comment` в POST только если он непустой. Если схема с `extra=forbid`, такой запрос даст 422.
- **Нужно:** добавить `comment` (макс. 1000) в `ReviewCreateSchema`.

### 5. Редакторская (админская) оценка
- **Сейчас:** признака `from_admin` нет. Админ создаёт обычный отзыв.
- **Фронт:** блок «оценка редакции» и форма оценок в админке выключены флагом `adminReviews`; рейтинг напитка — среднее по всем отзывам.
- **Нужно решение:** нужна ли редакторская оценка в MVP. Если да — признак в `ReviewSchema` (например `from_admin`) и права на его установку.

### 6. Публичное имя пользователя
- **Сейчас:** у пользователя только `email`; поля `username` нет.
- **Фронт:** показывает локальную часть e-mail (до `@`). Для чужих отзывов e-mail показывать нельзя.
- **Нужно:** поле `username`/`display_name` в `UserCreate`/`UserRead`/`UserUpdate` и в отзывах. Пока его нет, авторы отзывов не показываются.

## Уточнения

### 7. Картинки напитков
- В схеме напитка нет признака «картинка есть». Фронт всегда ссылается на `/api/v1/energy-drinks/{id}/image`; без картинки — 404 и битая `<img>`.
- **Нужно:** `has_image: bool` (или `image_url`) в `EnergyDrinkSchema`/`EnergyDrinkWithReviewsSchema`.

### 8. Один напиток по id
- `GET /energy-drinks/{id}` нет. Фронт ищет в общем списке (кэш 60 с).
- **Нужно:** либо эндпоинт, либо подтвердить, что список остаётся единственным источником.

### 9. Даты напитков
- Нет `created_at`, поэтому не работает бейдж «новинка» и сортировка по новизне.
- **Нужно:** `created_at` (и `updated_at`) в схемах напитка.

### 10. Пагинация
- Максимальный `limit` не указан; фронт забирает всё страницами по 100 (`shared/api/paginate.ts`).
- **Нужно:** максимальный `limit` (если меньше 100, фронт падает на 422), желательно — общее число записей (заголовок или поле).

### 11. Дубли отзывов
- Может ли один пользователь оставить несколько отзывов на один напиток? Фронт предполагает «один отзыв на напиток» (после создания показывает форму правки).

### 12. Шкала и `overall`
- Оценки `0–5`, `overall` обязателен. Фронт шлёт оценки 1–5 и `overall` = среднее шести оценок с одним знаком после запятой.
- **Нужно:** подтвердить формулу `overall` или считать его на бэке (тогда убрать из тела).

### 13. `ReviewUpdateSchema`
- Поля `Optional`, но без `default` → в pydantic v2 они обязательные. Фронт шлёт все поля. Если задумано частичное обновление — нужны `= None`.

### 14. Подтверждение e-mail и вход
- Можно ли залогиниться до подтверждения e-mail? Фронт после регистрации сразу логинит (как раньше). Если нельзя — нужен другой флоу.
- Куда ведёт ссылка в письме подтверждения / сброса пароля (URL страницы фронта и имя параметра `token`)? Страниц `/auth/verify` и `/auth/reset-password` на фронте пока нет.

### 15. Время жизни токена
- Cookie с токеном живёт 30 минут (как JWT). Есть ли refresh? Без него пользователя выкидывает каждые 30 минут.

## Выключено флагами (в API нет)

Включение: `NEXT_PUBLIC_FF_<ИМЯ>=1` при сборке фронта. Включать только когда бэк вернёт эндпоинт.

| Флаг | Фича | Что нужно от бэка |
| --- | --- | --- |
| `favorites` | Избранное | `GET /auth/me/favorites`, `POST`/`DELETE /auth/me/favorites/{id}` |
| `emojiReactions` | Эмодзи на отзывах | `GET`/`POST`/`DELETE /reviews/{id}/emojis` |
| `avatars` | Аватарки | `POST`/`DELETE /auth/me/avatar`, `POST .../preset`, поля `avatar_*` в `UserRead` |
| `submissions` | Заявки на добавление напитков | `/add-requests` (список, создание, статус, картинка) |
| `achievements` | Достижения и бейджи | счётчики в `/auth/me` (`first_reviewer_count`, `emoji_given_count`, `is_top10`), `author_badges` в отзывах |
| `reviewAuthors` | «Мой отзыв», автор и комментарий | пункты 2, 3, 6 выше |
| `adminReviews` | Редакторская оценка | пункт 5 выше |
